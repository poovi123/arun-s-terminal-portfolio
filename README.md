# Arun's Terminal Portfolio

Build a polished, responsive single-page personal portfolio for Arun, a Full Stack Developer, using the supplied design brief's "Idle Finance" dark terminal visual language adapted for a developer portfolio.

Design system to follow:
- Deep navy canvas #17202e, slightly lighter card surface #202a3e, text white #ffffff and muted gray #cdd0d6, cyan #6ae4ff as the only accent.
- Open Sans for headings and body (weights 400, 600, 700), tight tracking on large display type. Page max width 1200px, 80px major section spacing, 24px card padding, 15px card corners, pill buttons.
- Radial blue atmosphere behind hero only. Keep sections flat, hairline-bordered, no card shadows, no extra accent colors or light surfaces. Meet accessible contrast and keyboard navigation.
- Navigation with ARUN. wordmark, About / Skills / Projects / Contact anchors, plus white pill "Download résumé" button.
- Hero headline: "I build for the" then cyan "web." Short intro describing Arun as a full-stack developer exploring frontend, backend, and AI integrations. Add primary "Explore projects" and cyan outlined "Get in touch" actions. Use decorative code-terminal panel/abstract UI visualization instead of fabricated personal photography.
- About section with concise copy based on: passionate full-stack developer interested in frontend and backend technologies, open-source contributions; include a small quote block with the Martin Fowler quote already present in source page, attributed properly.
- Skills section with active skills HTML, CSS, JavaScript, Core Java, JDBC, JEE, Spring, Hibernate, MongoDB, SQL. Separately label learning next: React.js, Next.js, Node.js, Express.js, AI integration. Soft skills: communication, problem solving, team collaboration. Languages: English, Hindi, Kannada.
- Project cards for Task Manager App, Weather Dashboard, and Time Table. Avoid invented descriptions, metrics, tech stacks, live URLs, or source links. Make each card visually compelling with a small CSS-made preview graphic, title, and clearly editable "Project details coming soon" copy/disabled-looking non-link label rather than fake buttons. Keep structure easy to fill with accurate case study content later.
- Contact section with a direct contact CTA, but do not invent a working email or social URL. Put contact address behind one obvious editable placeholder value (e.g. update-me@example.com) and label it clearly in code/content so it can be replaced; prefer avoid displaying a misleading contact address in the UI, instead show a "Contact details to be added" note. Do not expose phone number.
- Include responsive mobile layout and functioning mobile navigation, smooth anchor navigation, subtle tasteful reveal interactions, reduced-motion support, footer/back-to-top. Do not include broken external assets. Use local/CSS visuals and lucide icons if available.
- Build a cohesive complete website, not a wireframe. Don't publish/deploy.
